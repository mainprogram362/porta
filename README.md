# PORTA

PORTAは、メディア整理・ファイル操作・動画変換・ローカルAIなどをまとめた、
個人用・ローカル専用のアプリ群です。

Firefoxの既存ウィンドウ・タブを選んで操作するカートリッジ機能の初期版を追加しました。
「自動操作」から作成・使用画面を開けます。初回の拡張機能導入、対応範囲、未検証事項は
[Firefoxカートリッジの手順](docs/browser-automation.md)を参照してください。

## 構成

```text
porta/
├── persistent_settings.json          # 外部ユーザー領域への入口設定（Git管理外）
├── integrated_backends/      # PORTAから呼ぶ同梱実行エンジン
├── scripts/
│   └── main.py                 # 通常利用の起動入口
├── src/
│   ├── apps/                   # 完成した画面とアプリ固有の処理
│   ├── automation/             # デスクトップ操作・ブラウザ通信と形式検査
│   ├── foundation/             # パス・ファイル・文字列の基本処理、旧import互換入口
│   ├── runtime/                # プロセス・単一起動・作業状態
│   ├── settings/               # 永続設定・ユーザー領域
│   ├── records/                # 対応表のモデル・加工・通信
│   ├── gui/                    # 再利用できる画面部品・固定アセット
│   └── media/                  # 動画・ダウンロード・メディア情報の基盤処理
├── requirements.txt
└── README.md
```

`apps/launcher/catalog.py` がメインメニューに出す完成アプリを登録します。
空の分類はメインメニューに表示されません。

`integrated_backends/` は、7-ZipなどをPORTAが内部機能から呼び出すための実行エンジン置き場です。
単体起動を約束せず、なくてもPORTAの起動は妨げませんが、対応する機能だけが利用不可となります。

`__pycache__`、`.pytest_cache`、`.ruff_cache` は生成物であり、ソース構造には含めません。

外部のユーザー領域は場所を設定して使い、アプリの親フォルダを暗黙の置き場とは扱いません。
その中を `config/`、`local_data/`、`private/`、`cache/` に分けます。アプリ直下には
この外部領域を指す `persistent_settings.json` だけを置きます。
すべての設定のパス欄では `@HOME`、`@PORTA`、`@USER`、`@CONFIG`、
設定ファイル基準の相対パス、絶対パスを使えます。`~` と環境変数は使いません。

```text
{
  "user_root": "@PORTA/porta_user"
}
```

```text
任意の場所/porta_user/
├── config/
│   └── shared/
│       └── external_program_locations.json # 明示登録する外部プログラム置き場
├── local_data/
│   ├── ai/models/
│   ├── ai/runners/
│   ├── dictionaries/
│   └── templates/
├── private/
└── cache/
```

## 内部の境界

- `foundation` はパス・ファイル・文字列などの基本処理を担当します。移行済みモジュールの旧importも互換入口として残します。
- `settings` は設定の配置・読み書き・ユーザー領域、`runtime` は実行管理、`records` は対応表を担当します。QtのIPCは実行管理・対応表の通信部分に限定します。
- `automation/browser` は画面なしで使えるFirefox通信とカートリッジの形式検査を担当します。
- `media` は画面を持たないメディア処理です。アプリ画面から再利用します。
- `gui` はアプリ固有の文言や保存処理を持たない共通部品です。パス入力は小入力・一覧表・OS連携に分離しています。
- `apps` は画面と操作手順を組み立てます。大きな画面固有処理は、同じアプリ配下のworkflowやadapterへ分離します。

完成画面の外周余白は `AppPageLayout`、最上部の「戻る・画面名・永続設定」は
`AppHeader` を使います。画面固有の操作欄は、その下で用途ごとに組み立てます。

依存方向は原則として `apps → gui / media / automation / records / settings / runtime / foundation` とし、基盤側から完成画面をimportしません。
配置と互換性の詳細は [srcの構成方針](docs/src-architecture.md) を参照してください。
メインメニューへ未登録で、公開APIからも参照されない試作はソースへ残さず、必要になった時点で現在の基盤上に作り直します。

## 永続設定とプライバシー

通常利用では、作業対象・操作結果・画面状態を記録しません。設定の編集または
出力を明示実行した場合だけ、その対象へ書き込みます。個人環境に依存する設定は
外部ユーザー領域の `config/` に置き、Git管理しません。保存先の変更・初期化はアプリ内の
「CONFIG・永続設定」から行えます。

各JSON設定は共通エディタの「通常表示」と「元データ直接編集」を切り替えられます。
通常表示はJSON型・厳密な保存値・不可視文字・パスの解決結果を示し、配列を並べ替えられます。
元データ直接編集は従来どおりJSONを直接扱い、通常表示を構築できない内容も失わず修正できます。
ユーザー領域を確定できない場合、各アプリは内蔵雛形を読み取り専用で表示します。

「CONFIGを初期化」は現在のCONFIGを同じ親フォルダの
`config_backup_YYYYMMDD_HHMMSS/` へ退避してから、全アプリの設定雛形を新しく作ります。
雛形の準備や切り替えに失敗した場合は、初期化前のCONFIGへ戻します。

設定分類の「環境整備・確認」は、本体とユーザー領域の構造、設定ファイルの形式、
設定内の参照先、Python依存関係、FFmpeg・7-Zip・mpvなどを読み取り専用で点検します。
全設定雛形の原本も表示でき、実ファイルがない場合は各アプリが同じ雛形を
メモリ上で代替利用できることを確認します。この点検自体はファイルを作成・修復しません。

`external_program_locations.json` は `locations` 配列に明示登録した場所だけを読みます。

```json
{
  "locations": [
    "@HOME/porta-external-apps"
  ]
}
```

PORTAは各置き場の直下にある `start.sh` 付きフォルダだけを一覧に出し、登録していない場所を自動探索しません。

Git/GitHubへ送信する機能はアプリにありません。ファイル操作は明示実行時だけ行い、
コピーとZIPは指定先内の専用一時領域で作成・検査し、同名を置き換えずに完成名へ公開します。
通常のコピー・移動・リネーム等が途中で止まった場合、完了済みの出力や名前は保持し、
完了した段階と停止理由を表示します。公開先を名前だけで判定して自動削除・巻き戻ししません。
再実行する場合は残った対象を選び直して、新しい確認画面を開いてください。
別領域への移動は、内容照合と元削除前の再確認を行います。追加の全量読み取りがあるため、
サイズだけを調べる方法より時間がかかります。移動中の元データを他のアプリで編集しないでください。
強制終了・電源断では、指定先に `.porta-copy-*` / `.porta-zip-*` の一時領域が残ることがあります。
通常の取消・エラーでは専用一時領域を片付けますが、公開済み出力は保持します。

## 起動

```bash
cd porta
./start.sh
```

`start.sh` は自分の位置からPORTAルートを決めます。`.venv` がない場合やPORTAの移動を検出した場合は、
確認後にその場所用の仮想環境を作り、CONFIG・AIモデル・ユーザーデータには触れません。
`scripts/main.py` も必要な `src/` を自動でimportパスへ追加するため、`PYTHONPATH` の指定は不要です。

## 画面の終了

無操作による自動終了・自動保留は行いません。画面は手動で操作・終了します。

## 暗号化・保護

「暗号化・保護」は方式を先に選び、その方式で実行できる操作だけを表示します。現在はLUKSの
開く・マウント、VeraCryptの作成・マウント・状態確認・解除、7z／ZIPの圧縮・暗号化と
解凍・復号、RARの解凍を利用できます。VeraCryptは安全な非対話CLIと標準入力対応を確認できた
環境だけで操作を有効にし、利用できない場合は検出理由を表示します。7zでは
ファイル名・フォルダ構成も暗号化できますが、ZIPでは互換性のため名前は隠れません。
Cryptomatorは準備画面のみで、まだ外部アプリ・保管庫を操作しません。
パスワード、復旧情報、鍵の内容、実行履歴は保存しません。

アーカイブ操作は対象をこの画面で固定した後、専用の確認画面で出力先・パスワード・詳細を確認して
実行します。ファイルマネージャーの既存の圧縮・解凍操作は変更していません。

ウィンドウは用途に合わせて自由にサイズを変更できます。最初のメニューは、現在の文言・フォント・表示倍率からボタンの必要寸法と列数を計算し、最小サイズでも全入口をスクロールなしで表示します。機能画面は利用者が選んだサイズを維持し、入りきらない操作欄だけをスクロールで確認できます。画面の情報量から本体の最小サイズを引き上げません。複数行欄は固定ピクセルではなく表示行数、表の補助列は見出しと代表値、コンパクトな操作ボタンはQt自身の必要寸法から大きさを決めます。ファイルマネージャーの作業一覧はフルパスを省略せず表示し、長いパスは横スクロールで確認します。お気に入りは「フルパス表示」で切り替えられます。
ファイルマネージャーの分割線はドラッグして広さを調節できます。操作・状態欄は一覧のスクロール外にあります。
通常の実行確認画面は処理中も応答し、「処理を取り消す」で安全な処理境界での停止を要求できます。
「保留まとめ」と保留再開用の起動オプションは廃止しました。
一時対応表は引き続き独立したプロセスで保持し、本体を閉じても残ります。

## 本体の単一起動

同じユーザー・一時領域で同じ配置場所のPORTAをもう一度起動すると、既存本体を前面へ
出してメインメニューを表示します。独立した作業の入力・処理は維持します。
確認ダイアログを表示している場合は、閉じた後にメニューへ切り替えます。
別の配置場所のPORTAは別本体として起動できます。導入前から動いている旧版本体には
受信機能がないため、この機能を使うには一度手動で終了して起動し直してください。

外部パス、一時対応表の取得・出力も既存本体に渡します。これらの明示的な入力は
新しい画面で開き、既存画面の入力を上書きしません。確認ダイアログの表示中は受け付けた
要求をメモリ内で待機させ、閉じた後に順番に開きます。

通常は、メインメニューと複数の作業タブを一つのPORTAウィンドウ・一つのプロセスで管理します。
機能ボタンは現在のウィンドウへ新しいタブを直ちに開きます。明示的に「別ウィンドウへ分離」した
場合だけ、新しいプロセスへ安全に移せる状態を渡し、受領確認後に元のタブを閉じます。
分離後のウィンドウは起動元に従属せず、起動元を閉じても作業を継続します。
外部パス・対応表・ファイルマネージャーからの通常の受け渡しは、現在のウィンドウの新しいタブへ渡します。
作業プロセス自体の終了・異常終了やOS再起動後の入力復元は行いません。
作業ウィンドウには「名前」「残す」「この作業を閉じる」があります。終了は作業側で確認し、
処理中や補助画面が残っている場合は拒否します。登録済み機能には状態報告を追加し、
将来の未対応画面や取得失敗は「状態不明」とします。
「PORTAの画面」は、メニュー・全作業タブ・分離したウィンドウ・対応表を同じ一覧に表示します。
前面表示と画面側での終了確認もここから行い、PID・内部処理は「プロセス詳細」に分離します。
一時対応表だけは共有するメモリ内データのため、専用1プロセスが各対応表IDを管理します。詳細は
[PORTA画面の管理](docs/work-processes.md)を参照してください。
ファイルマネージャーの画面Undoは最大50段階・概算16MiBまでメモリ内に保持します。

動画変換の「試し変換」は編集後の先頭15秒までを、実行装置名を含む別名で出力します。
CPU／GPUを同じ入力・編集条件で試し、実行詳細の時間・サイズと実際の映像を比較できます。
高速キーフレームカットと目標サイズ指定には併用しません。画質を自動判定する機能ではありません。

同時起動はロックで調整し、応答を確認できない場合はエラーを表示して追加起動を止めます。
受領確認は要求を受け付けたことを表し、その後にファイルが消えた場合などのエラーは
既存本体に表示します。前面化の最終判断はデスクトップ環境に従います
（[Qtのウィンドウ有効化](https://doc.qt.io/qt-6/qwidget.html#activateWindow)）。

通信先はOSの一時領域（通常 `/tmp/porta-main-UID/`）に置きます。ディレクトリは0700、
空のロックファイルは0600、ソケットは同じユーザー専用です。起動要求はディスクに
保存しません。異常終了でもOSがロックを解放し、次の起動で古いソケットを回収します。
競合を避けるため空のロックファイルは残します。

## テスト

自動テストはpytestに統一しています。
実行時依存の動作確認済み組合せは `requirements-runtime.lock`（Linux / Python 3.13）です。
起動時に仮想環境を作り直す場合も、この制約で導入します。既存環境を起動だけで更新しません。
開発環境の初回導入は次のとおりです。`/tmp` に置いた仮設テスト依存は不要です。

```bash
.venv/bin/python -m pip install -r requirements-test.lock
.venv/bin/python -m pip install -e . -c requirements-runtime.lock
```

```bash
cd porta
QT_QPA_PLATFORM=offscreen PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m pytest -q -p no:cacheprovider
```

## PORTAの画面とプロセス詳細

「PORTAの画面」で、メニュー、各ウィンドウ内の作業タブ、明示的に分離したウィンドウ、
個別の対応表をまとめて確認できます。
利用者向け一覧にはOSプロセスを混ぜません。「プロセス詳細」を開いた場合だけ、本体、
対応表サービス、FFmpegなどの内部処理を表示します。コマンドラインでは
`scripts/main.py --list-processes` がこの配置場所の診断一覧をJSONで返します。

識別にはPID、OS起動ID、プロセス開始時刻を使います。PIDが再利用されても古い作業情報を
新しいプロセスに結びつけません。画面の応答確認とプロセスの生存確認は別に扱い、
画面の応答が遅れても終了済みとは判断しません。

- `runtime/process_registry.py` が本体・補助プロセス・実行中作業の登録を統一します。
- `runtime/managed_process.py` がPythonからの起動を、`gui/process_tracking.py` がQtからの起動を追跡します。
- コピーなどのスレッド内作業も登録し、別のPIDがなくても実行中の作業として表示します。
- PORTAの別ウィンドウは起動元との所有関係を登録せず、それぞれが自分自身を登録します。
- 一時対応表は専用プロセスへIDで問い合わせ、利用者向け一覧には対応表ごとに表示します。
- 旧版などの未登録本体はPythonの起動入口を照合して表示します。ファイルとして `main.py` を開いているエディタ等は対象にしません。

登録情報は所有者専用の `XDG_RUNTIME_DIR/porta-processes/` に置き、使えない場合は
`/tmp/porta-processes-UID/` を使います。作業内容、対象パス、コマンド引数、秘密情報は
保存しません。終了済みの登録は監視・一覧更新時に除去し、実行履歴としては残しません。
登録先の障害は一覧に表示し、開始済みの処理を登録エラーで中断しません。

内部ライブラリが起動する子孫プロセスは定期観測で補います。観測前に終了・独立した
子孫や、既存の外部アプリへ起動要求だけを渡した場合の常駐先までは追跡を保証しません。
別の配置場所については、その版が登録したプロセスを対象とします。

一覧は確認専用です。自動終了は行いません。既存の `--close-instances` は
引き続き明示的な強制終了であり、未保存確認を行う通常終了ではありません。
終了対象は起動入口と開始識別情報を再確認し、PID再利用で別のプロセスへ信号を送らないよう
pidfdで固定します。pidfdを利用できない場合は終了要求を送りません。

実装上の参照: [Linuxのプロセス開始時刻](https://www.man7.org/linux/man-pages/man5/proc_pid_stat.5.html)、
[Qtのプロセス起動通知](https://doc.qt.io/qt-6/qprocess.html#started)。
