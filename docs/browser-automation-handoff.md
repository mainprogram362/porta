## 設計

各Firefoxプロファイルの拡張から `connectNative("porta_browser")`。
Native Hostが `/tmp/porta-browser-UID/ランダムID.sock` を公開し、PORTAが列挙する。
ディレクトリ0700・ソケット0600、所有者/種類/権限を確認。タブ情報のJSONファイルは作らない。
同じOSユーザーのプロセスは接続できる。ローカルの悪意ある同一ユーザープロセスを隔離する方式ではない。

選択キーは接続UUID＋ウィンドウID＋タブID。準備時に完全URLを照合し、文書IDも取得。
手順ごとに文書IDと完全URLを照合。タブ移動/閉鎖・再接続・想定外の文書変更・要素件数不一致なら停止。
DOMの意味の変更を完全検出するものではない。クリック/入力は利用者の実行操作と確認後に送る。
同じタブは作業UUIDによる10分のリースで排他。endはタブが閉じられた/移動した場合も解除可能。
停止は後続停止、送出済み操作を取り消さず自動再送しない。命令に期限を付け、遅れて届いた操作も期限で拒否する。
Qtワーカーを親画面に所有させ、既存のrunning_work判定に載せる。shutdownで停止とリース解除を要求。

操作はcheck/extract/fill/click/wait_page。wait_pageは直前クリック後、許可origin内の指定URLかつ新しい文書/URLを確認。
同じURLの旧ページを遷移完了と誤認しない。SPAの同じURL内での更新待ちや汎用要素待ちは未対応。
未知の実行結果を成功と見なさない。入力だけでサイトが保存する場合もある。
任意コード、ループ、iframe、新規タブ追従、新規ブラウザ起動、署名済み恒久導入、Snap/Flatpak対応は範囲外。

## 再開時の検証課題（別の実行環境が用意された場合のみ）

1. JSON検証テストと、既存catalog/GUI起動との互換性。
2. Firefoxを模したAPI/DOMで、対象変更・0/複数要素・期限超過・二重操作・同じURLへの遷移待ちを検証。
3. 分離したLinux/FirefoxでNative Messagingのフレーム、権限要求、複数プロファイル/ウィンドウ/タブ列挙、HTTPページの文書ID生成を検証。
4. タブ閉鎖・ウィンドウ移動・接続切断・応答喪失・停止・メイン終了時のQtワーカーの後始末。
5. 通常ページとSPAのクリック直後の応答、input/changeによるサイト側の変化、権限を取り消した際の挙動。
6. 多数タブ・長いURL・小さいウィンドウでの操作性。800KBの応答上限は明示エラーであり、無制限列挙ではない。

初回利用手順は別紙参照。利用者のFirefox設定やNative Host登録にはまだ触れていない。
