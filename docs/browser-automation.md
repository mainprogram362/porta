# Firefoxカートリッジ（初期版）

メニューの「自動操作」に「Firefox・カートリッジ使用」と「ブラウザ・カートリッジ作成」を追加しています。
既存のFirefoxに拡張機能から接続します。新しいFirefoxを起動したり、既存タブを閉じたりはしません。

**現時点では実行未検証です。ユーザー指定により、このPCではテスト・拡張機能導入・Firefox操作を実行していません。別の実行環境も提供されていないため、疑似環境での実行結果もありません。**

## 初回導入（利用者が行う操作）

初期版の対象は、通常インストールのLinux Firefox（128以降）です。Snap / Flatpak版のNative Messaging接続は別の設定が必要になる場合があり、この登録スクリプトでは対応しません。

1. PORTAのフォルダで次を実行します。Firefoxを終了する操作は含みません。

   ```sh
   .venv/bin/python scripts/install_browser_bridge.py
   ```

   `~/.mozilla/native-messaging-hosts/` に `porta_browser.json` と `porta_browser_launcher.sh` を作成します。
   既存登録がある場合は停止します。PORTAの配置やPython環境を移動した場合だけ、内容を確認して `--replace` で登録を更新してください。

2. 対象のFirefoxで `about:debugging#/runtime/this-firefox` を開き、「一時的なアドオンを読み込む」から、このリポジトリの `extensions/porta_firefox/manifest.json` を選びます。
3. 拡張機能ボタンを開き、接続名を「普段用」「調査用」などに変更して「接続」を押します。
4. **複数のプロファイルを使っている場合は、それぞれのFirefoxで2～3を行います。** 同じプロファイル内の複数ウィンドウには個別導入不要です。
5. 操作したいサイトのタブで拡張機能ボタンを開き、そのサイトの操作を許可します。遷移先も操作する場合は、そのサイトも許可してください。
6. PORTAの使用画面で「Firefox候補を更新」を押します。

一時アドオンはFirefoxの再起動で解除されます。初期版は署名済み配布物を含んでいません。恒久導入には別途署名・配布が必要です。
プライベートウィンドウを対象にする場合は、Firefoxの拡張機能管理でプライベート実行を許可する必要があります。

接続方式の根拠：[Mozilla Native Messaging](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/Native_messaging)、[一時導入](https://extensionworkshop.com/documentation/develop/temporary-installation-in-firefox/)。

## 対象の選択

一覧は「接続名・接続ID・プロファイルID → ウィンドウ → タブ」の順です。
URLは省略せず横スクロールで読めます。選択対象のURLも一覧下に表示します。
「選択タブを前面で確認」は、そのウィンドウ・タブを前面に出す明示操作です。

取得対象は、**拡張機能から接続され、Firefoxが拡張機能に公開しているウィンドウとタブ**です。
未導入・未接続のFirefox、別OSユーザーのFirefox、閲覧許可のないプライベートタブを含むとは限りません。
内部ページ（about:等）は表示できても操作対象外です。Firefoxの保護ページはhttpsでも操作を拒否されます。
一覧は更新時点の情報です。選択後のタブ移動・接続変更・URL変更は、実行時にも確認します。
非常に大量のタブや長いURLで応答が800KBを超える場合、接続エラーとして表示します。黙って一部だけを返しません。

## カートリッジを作る・使う

1. 作成画面でJSONを編集します。初期表示は `https://example.com/` のリンク抽出例です。
2. 対象URLとCSS selectorを書き換えます。Firefoxの開発者ツールで対象要素のCSS selectorを調べるか、使用画面の「要素を調べる」で一致件数・要素情報を確認できます。この確認では入力・クリックは送りません。
3. 「形式を確認」し、「名前を付けて保存」します。設定済みユーザー領域の `local_data/browser_cartridges/` を保存先候補にします。フォルダがまだなければ保存ダイアログで作成するか、任意の場所を選んでください。
4. 使用画面でタブを選び、カートリッジを読み込みます。全手順が表示されます。読み込みだけでは実行しません。
5. 「対象を固定して準備」→「次の1手順を実行」で確認します。「残りを連続実行」も可能です。
6. 抽出結果は画面に表示します。必要なら「結果を名前を付けて保存」で保存します。

`origins` は許可するサイトの一覧、各手順の `url` はその時点のページの完全URLです。
URLはクエリ・末尾スラッシュ・フラグメントまで一致が必要です。ブラウザが表示する完全URLを使ってください。

| action | 動作 | 主な項目 |
| --- | --- | --- |
| check | 要素の存在と一致件数を確認 | selector、任意のtext完全一致 |
| extract | 要素から情報を抽出 | selector、attribute（text/href/src/value） |
| fill | 通常の入力欄へ値を設定 | selector、value |
| click | 要素へクリックを送出 | selector、任意のtext完全一致 |
| wait_page | クリック直後の指定URLへの遷移を確認 | url、timeout（1～30秒） |

複数抽出だけは `many: true` を指定できます。`limit` は1～500件、既定100件です。
それ以外は対象がちょうど1件であることが必要です。0件・複数件なら停止します。
カートリッジは最大256KiB・100手順、抽出結果は1手順100000文字までです。
`wait_page` はクリックの直後だけ指定できます。同じURLへの再読込なら新しい文書を待ちます。
ページの表示完了はサイト内の非同期処理の完了を保証しません。次のcheckで必要な要素を確認してください。

## 停止と限界

- 操作対象は接続ID・ウィンドウID・タブIDで固定します。別のアクティブタブへ追従しません。
- 操作中に文書が差し替わった場合も停止します。明示的なwait_pageだけが文書の切り替えを受け入れます。
- 同じタブへの複数PORTA作業からの同時操作を拒否します。固定は準備から10分で失効します。
- 停止ボタンは後続手順を止めます。送出済みの入力・クリックは取り消しません。通信は通常最大35秒でタイムアウトし、不明な操作を自動再送しません。
- クリックの応答はサイト側の保存・送信の成功を保証しません。入力イベントだけで保存するサイトもあります。
- CSS selectorが別の意味の要素に一致する変更までは検出できません。重要な操作にはtext条件や先行checkを付け、1手順ずつ確認してください。
- iframe内部・閉じたShadow DOM・OSダイアログ・新規タブへの自動追従・任意JavaScript・ループ・操作録画・新規ブラウザ起動は初期版の対象外です。
- 手動操作や他の拡張機能の操作をロックするものではありません。実行中は対象タブの手動操作を避けてください。

タブ一覧・抽出結果は自動保存しません。カートリッジを保存すると入力値も含まれます。
拡張機能には接続名・プロファイル識別子・利用者が許可したサイト権限が残ります。
連携ソケットは同じOSユーザーのみアクセス可能です。同じユーザー権限の他プログラムからの操作を隔離する境界ではありません。

終了は拡張機能の「切断」で行えます。登録を撤去する場合は拡張機能を削除した上で、導入時に作った上記2ファイルを削除します。他のNative Messaging登録は削除しないでください。
