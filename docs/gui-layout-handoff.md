## 最新の実装結果（全体改修）

- 全14機能を共通の `ScrollablePageStack` 内に保持。画面を開いても利用者のウィンドウサイズを変えず、必要な場合だけスクロールする。元の画面オブジェクト・入力・作業切替・スクロール位置を保持する。
- メニュー初期800×540、最低600×400。高密度画面の最低サイズをウィンドウ全体へ強制しない。隠れたページの寸法を参照しない `CurrentPageStack` を、FM操作欄・台帳・JSON設定編集にも適用。
- `AppPageLayout.heightForWidth` は可変エディターの推奨高さではなく、折返しを含む必要最低高さを返す。これにより空の編集欄が必要以上に縦スクロールを発生させない。Qt内部の仮想呼出しに再入防止が必要なのでコメントを残した。
- `FlowLayout` を追加し、FM・動画変換・レスビューア等の操作ボタンを幅に応じて折り返す。
- FM作業一覧と一対一出力先は、フルパスを省略せず、必要時に横スクロールする。パスの長い日本語・空白・同名の別フォルダを区別できる。入力末尾行の案内も列幅計算に含める。
- FMは幅960未満で一対一出力先／リネーム欄を縦配置。条件選別を短いラベルのフォームにし、一覧の最低行数を4行へ整理。通知はコピー可能な読取専用1行入力にし、長文はツールチップでも確認できる。チェック状態・青選択・実行確認の既存仕様は保持。
- お気に入りに「フルパス表示」切替を追加（初期は従来どおり末尾名）。この表示設定はその画面内だけで保持し、永続設定は勝手に変更しない。
- リネームの規則欄・予定欄は縮小可能にし、変更前後のファイル名も省略せず横スクロールで確認できる。
- テキスト加工・動画変換・メディア情報・台帳の過大な明示最低サイズを縮小。台帳の内側の強い幅制約も緩和。
- 動画変換のプレビュー／結果、掲示板保存のURL／確認結果、YouTubeの入力／結果、AIの実行状況／入力、共通複数行入力の固定高さを緩和。情報一覧や本文へ空間を配分する。
- 設定画面の説明を折り返し、長い入口作成ボタンを短縮。共通パス入力はツールチップで完全な入力値と既存説明を両方確認できる（HTML風のファイル名もエスケープ）。
- FM最終確認ダイアログと永続設定入口ダイアログは、初期の広さを維持しつつ小さく変更可能にした。一時対応表は既存の独立プロセス・可変一覧構成を維持。

## ユーザーと確認した方針

- 厳密さを重視する。特にファイルマネージャーは異なるディレクトリの対象が混在するため、作業一覧はフルパスが基本。名前だけへの置換や自動的な親パス省略を既定にしない。
- お気に入り等の近道はコンパクト表示でもよい。フルパス確認を選べるようにする。
- 作り手が固定サイズを強制するのでなく、ユーザーが状況に応じて自由にリサイズする。画面の半分程度にし、隣にブラウザや標準ファイルマネージャーを置くことも想定。
- メニューは小さく、ファイルマネージャーは中程度、複雑な編集画面は必要に応じて大きくできる。すべての画面を単一の大きな最低サイズに揃えない。
- 重要な入力、対象の識別、操作結果、安全上必要な説明を維持し、重複説明・不要な余白・固定高さを合理化する。
- 折りたたみ/タブへの移動を全面的に許可する回答はまだない。通常のレイアウト改善は依頼範囲内だが、操作体系を大きく変える判断が必要なら質問する。
- トークン/コンテキストに余裕がなくても全体改修を完了扱いにしない。実装・検証を小分けにし、未完了箇所と次の一手を残す。

## 作業上の注意・再開方法

- ワークツリーは非常にdirty。既存変更・未追跡ファイルはユーザーの成果。reset/checkout等で戻さない。
- リポジトリ内AGENTS.mdは調査時見つからなかった。rgは以前から未導入だったため必要ならgrep/findを使う。
- 編集はapply_patch。実ユーザーの文書や設定を書き換えるGUI操作は検証に使わない。
- エージェントの並列利用は依頼されていないので行っていない。
- 自動終了/自動保留は撤去済み。単一起動、作業画面の再利用/新規作業、浅い画面の再起動時メニュー復帰は実装済みで維持する。

