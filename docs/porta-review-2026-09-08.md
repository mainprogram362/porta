# PORTA 精査・改善提案（2026-09-08）

追記: この調査に基づく修正と検証結果は [修正進捗](repair-progress.md) を参照。以下は修正前の調査記録。

今回は調査のみ。アプリのソース・設定・ユーザーデータは変更していない。この報告書だけを追加した。
レイアウト、作業保持、ファイル操作、終了処理、設定、依存関係とテストを横断して確認した。全コードの正当性や実機での全操作を保証する監査ではない。

## 修正を優先する問題

### 1. コピーの競合で、別の処理が作ったファイルを削除・上書きできてしまう（最優先・再現済み）

根拠: `src/apps/file_tools/file_manager/copy_workflow.py:270`、`:299`、`src/foundation/filesystem.py:138`。

- コピー開始前に出力名の空きを確認しても、実際の作成までに別プロセスが同名を作れる。
- `pending_output` は作成成功前に設定され、失敗時に自分で作成した証拠がなくても削除対象へ入る。
- `copy_or_move` が存在を検出して拒否した場合でも、その競合ファイルをロールバックで削除してしまう。
- 最後の存在確認を通過した後の競合では、`shutil.copy2` が既存ファイルを上書きする。

一時ディレクトリのみで実験。実際のコピー関数を呼ぶ直前に別の書き手のファイルを作る注入で、エラー後にそのファイルが消えた。さらに `copy2` 直前にファイルを置く注入で、その内容がコピー元の内容に置き換わった。実環境での発生頻度を計測したものではない。

改善: ファイルは排他的な新規作成、同一領域の移動は非上書きを原子的に保証する仕組みへ変更。存在確認の追加だけでは解決しない。失敗時は、当該実行が所有する出力だけを処理し、所有を確認できないものは残して報告する。Linuxの非上書きrename等の対応可否も実装時に確認する。移動・リネームの `exists` → `rename` 経路とロールバックも同じ観点で検査する。

Python仕様も参照: [shutil.copy2 / copy](https://docs.python.org/3/library/shutil.html#shutil.copy2)。

### 2. 部分的に処理済みでも「実行していません」と表示する（高・再現済み）

根拠: `src/apps/file_tools/file_manager/operation_confirmation_dialog.py:169`、`move_workflow.py:88`。

例外を一律に「実行していません」と表示している。一方、別領域への移動はコピー後の元データ削除が途中で失敗すると、既に削除した元は戻らない設計。

一時データ2件で別領域分岐を模擬し、2件目の元削除を失敗させた。元の存在は `[False, True]`、出力は両方存在するのに、画面の先頭は「実行していません」になった。実ディスク跨ぎの障害を起こしたものではなく、分岐と例外処理への注入実験。

改善: 結果を「未開始／完了／一部完了／取消／復旧失敗」に分け、項目ごとの元・出力・実施済み段階・残存物をメモリ内に持つ。再実行ボタンも残った対象から計画を作り直す。利用者が明示したときだけ結果を保存する。

### 3. 通常のファイル操作がGUIスレッドで実行される（高・再現済み）

根拠: `operation_confirmation_dialog.py:158` → `operation_service.py:81`。

通常確認画面は `execute_operation` をクリック処理から同期呼出しする。作業登録用の `runtime_activity` は別スレッド化ではない。

書込処理を250ms待つ代替関数に置換して測定。実行スレッドはGUIスレッドで、その間10ms周期のQTimerは0回発火。実ファイルはコピーしていない。

改善: 通常操作とクイック操作で共通の実行担当を用意し、進捗・取消要求・結果をシグナル等で受け取る。取消は安全な処理境界で受け付ける。画面を固めず、作業切替と終了判断もできるようにする。単に `processEvents()` を挟む修正では、処理途中の再操作を招くため不十分。

参照: [Qtのworkerによるスレッド処理](https://doc.qt.io/qt-6/qthread.html#detailed-description)。

### 4. 本体終了時の作業停止・破棄の扱いを揃える（高・終了受付を再現）

根拠: `src/apps/launcher/main_menu/window.py:509`、`src/apps/media_tools/board_response_archive/window.py:176`。

本体は `shutdown` がある画面だけを呼ぶ。掲示板保存画面は親付きQThreadを使うが、この共通終了処理に接続されていない。動画のQProcessや各クイック処理も含め、終了判断が統一されていない。

掲示板画面に短時間動く模擬QThreadを置き、本体を閉じると `close() == True` かつ `isRunning() == True` を確認した。異常終了を意図的に発生させず、実験後にスレッド完了を待って回収した。クラッシュそのものの再現を主張するものではない。

実行中QThreadの破棄はQtでクラッシュ要因になる。[Qtのデストラクター仕様](https://doc.qt.io/qt-6/qthread.html#dtor.QThread)。

改善: 全作業が「実行中か／停止できるか／未保存入力があるか」を返す共通契約を持つ。本体終了時に集約し、必要な場合だけ待機・取消・破棄を判断する。強制的なスレッド停止や一律の自動終了にはしない。

### 5. 別領域への移動で、内容の照合を選べるようにする（中〜高・限界を再現）

根拠: `move_workflow.py:130`。

現在のファイル照合はサイズ一致、ディレクトリは項目構成とサイズ等の一致。4バイトの `AAAA` と `BBBB` に `_paths_match` がTrueを返すことを確認した。コピーが実際にデータを壊すと実証したわけではなく、現行の照合が内容同一を証明しないという意味。

改善: 少なくとも「サイズ照合」と「内容照合」を区別して表示。厳密モードでは元を削除する前に内容ハッシュ等を確認し、元の更新・置換も検出する。追加の全量読取は遅くなるため、その代償を明示する。

## テスト・環境整備

- 全体テストを今回も再実行し、545 passed / 13 failed（59.38秒）。ログは `/tmp/porta-review-tests.log`。13件は直前の既知一覧と同じ。
- 既知だから無害とは扱わない。雛形の種類追加に追従していない期待値、テスト内の未定義 `app`、パス前後空白・設定パス・ショートカットの仕様不一致を分けて解決する。テストを現状へ機械的に合わせず、入力仕様を確定してから正す。
