# PORTA画面の管理（2026-09-14）

## 原則

一つのPORTAウィンドウは一つのプロセスで動き、その中にメインメニューと複数の作業タブを持てる。
通常の機能起動は現在のウィンドウへタブを追加する。明示的に分離した場合だけ別のPORTA
ウィンドウとプロセスを作る。分離後は起動元との所有関係を持たず、起動元が終了しても継続する。

確認ダイアログ、プレビュー、ファイル選択、右クリックメニューなど、作業画面に付随する
一時画面は同じプロセスで動く。一時対応表だけは共有するメモリ内データと識別番号を扱うため、
専用1プロセスが複数の対応表ウィンドウを管理する。

## 起動と受け渡し

メニューで機能を選ぶたびに、現在のPORTAウィンドウへ新しいタブを作る。各タブは一時的な
管理受付先を持つため、別のPORTAウィンドウからも存在と状態を確認し、そのタブを直接表示できる。

「別ウィンドウへ分離」は、安全に表現できる入力状態を `runtime/work_process.py` から匿名パイプで
一度だけ渡す。移動先の受領確認後に元タブを閉じる。入力をコマンド引数や一時JSONファイルへ
保存せず、分離先は自分のPID・画面種別・状態を登録する。

同じPORTAを通常起動した場合だけ、既存のメインメニューへ要求を転送する。外部パス、対応表ID、
対応表のテキスト出力もメニューが受領し、新しい作業タブへ渡す。既存作業の入力は上書きしない。

## 「PORTAの画面」

利用者向けの入口は「PORTAの画面」一つとする。次を同じ一覧へ表示する。

- メインメニュー
- 各PORTAウィンドウ内の通常タブ
- 明示的に分離した作業ウィンドウ
- 個別の一時対応表
- プロセスは存在するが管理通信へ応答しない画面

一覧には画面名、種類、4段階の状態、理由を表示する。PID、起動元、内部処理などは通常一覧へ
出さず、「プロセス詳細」で確認する。選択したウィンドウまたはタブの表示と、画面側での終了確認を
行える。通信が不明な場合は自動再送も強制終了も行わない。

状態は次のとおり。

- 1: 初期状態
- 2: 設定・入力あり
- 3: 保持する作業あり
- 4: 処理実行中
- 不明: 未対応、取得失敗、通信失敗

不明を「終了してよい」とは判断しない。終了要求は対象画面が再確認し、処理中や補助画面が
残っていれば拒否する。

## 対応表

対応表ごとに識別番号を付け、必要なときだけ専用プロセスへ問い合わせる。ファイルマネージャーは
対応表IDを持ち、取得時に版番号と内容を受け取る。統合一覧にはサービスプロセスを1件として
表示せず、対応表を1画面ずつ表示する。最後の対応表を閉じると専用プロセスも終了する。

## 実装

- `runtime/work_process.py`: 作業起動、画面状態の取得、前面表示・終了確認の要求
- `apps/launcher/work_tabs.py`: 同一ウィンドウ内のタブ、状態受付、明示的な分離
- `apps/launcher/work_window.py`: 分離後の1作業ウィンドウを所有するQMainWindow
- `apps/porta_control/work_overview.py`: メニュー・タブ・分離ウィンドウ・対応表を統合する一覧
- `apps/porta_control/diagnostics/process_center.py`: PIDと内部処理を扱う診断詳細
- `runtime/process_registry.py`: PID再利用を避けるための一時的な生存登録
- `records/record_service.py`: 対応表IDによる問い合わせ
- `apps/launcher/record_center.py`: 対応表専用プロセスと各対応表ウィンドウ

作業IPCは `/tmp/porta-works-UID-配置ハッシュ/`、プロセス登録はログイン用一時領域を使う。
所有者と権限を検査し、履歴、対象パス、文書内容、コマンド引数は登録しない。PIDだけでなく
OS起動IDとプロセス開始時刻を照合し、PID再利用による取り違えを避ける。

画面を増やすほどPythonとQtのメモリ使用量は増える。同じ設定を複数画面で開くこと自体は許可し、
別画面の存在を警告する。読み込み後に保存対象が変更された古い画面からの上書きは拒否する。
